# Brief: ปรับปรุงหน้า "อาคาร 3 มิติ" (equiplog)

เอกสารนี้ให้ AI/นักพัฒนาอีกคนทำงานต่อได้โดยไม่ต้องถามกลับ แนบรูปอ้างอิงสไตล์มาด้วย (isometric cut-away floor plan: ผนังหนา ห้องมองจากมุมสูงเฉียง พื้นหลังเทาอ่อน) ผู้ใช้ตอบสนองต่อสไตล์ในรูปนั้นโดยตรง

## 1. เป้าหมาย

หน้า `/building` แสดง **แผนผังชั้นของอาคารแบบ 3 มิติ** ให้ช่างและผู้ดูแลเห็นว่า **อุปกรณ์จริง** (Chiller, Pump, เครื่องปรับอากาศ) อยู่ห้องไหน ชั้นไหน และสถานะบำรุงรักษาเป็นอย่างไร กดที่เครื่องแล้วแผงข้อมูลเลื่อนเข้ามาจากขวา

**สิ่งที่ต้องเน้น:** อุปกรณ์และสถานะการบำรุงรักษา **ไม่ใช่** ความสวยของห้อง ห้ามใส่เฟอร์นิเจอร์ โต๊ะ เก้าอี้ ต้นไม้ หรือรายละเอียดตกแต่งที่ไม่เกี่ยวกับงานบำรุงรักษา

**ปัญหาปัจจุบัน:** ผู้ใช้ "ไม่ประทับใจ" โมเดล ตอนนี้ดูเป็นกล่องเรียบๆ ขาดความรู้สึกของงานออกแบบมืออาชีพ เมื่อเทียบกับรูปอ้างอิง (ผนังมีความหนาและน้ำหนัก แสงเงา วัสดุ สัดส่วนห้องดูเป็นอาคารจริง)

## 2. Non-goals / ห้ามทำ

- ห้ามใส่ของตกแต่ง (โต๊ะ เก้าอี้ ฯลฯ) ผู้ใช้บอกชัดว่าไม่เอา
- ห้ามหมุนอัตโนมัติ (ผู้ใช้ไม่ต้องการ auto-rotate 360°) หมุนเมื่อผู้ใช้ลากเท่านั้น
- ห้ามมีพื้นสี่เหลี่ยม/กรอบรองใต้โมเดล และห้ามมี card ครอบโมเดล โมเดลต้องเด่นบนพื้นหลังหน้าโดยตรง
- ห้ามมี scrollbar ของหน้า ความสูงโมเดลต้องพอดีจอ (ตอนนี้ใช้ `h-[calc(100dvh-400px)] lg:h-[calc(100dvh-335px)]`)
- ห้ามใช้ `<Html>` ของ `@react-three/drei` (ดูข้อ 6)
- ห้ามดึงรูป/โมเดล/ฟอนต์จาก CDN ภายนอก (host ไม่ควรพึ่งภายนอก) ถ้าใช้ไฟล์ `.glb` ต้องเก็บใน repo หรือโฟลเดอร์อัปโหลดของแอป

## 3. สไตล์ที่ต้องการ (อ้างอิงรูป)

- มุมมองเหมือน isometric ใช้ perspective fov ต่ำ (~25–30) หรือ orthographic ก็ได้ ตั้งกล้องจากมุมสูงเฉียง เห็นพื้นและด้านในห้องชัด
- ผนังมีความหนา สีผนังนอกกับผนังในต่างกันเล็กน้อย (ในรูป ผนังนอกเข้ม ผนังในขาว) ผนังเตี้ยพอที่จะไม่บังอุปกรณ์เมื่อมองจากมุมสูง
- พื้นต่างโทนกันระหว่างห้องกับทางเดิน มีเงานุ่ม (soft shadow) และแสงที่ทำให้เห็นมิติ
- สีสะอาด โทนกลาง-อ่อน ให้อุปกรณ์และสีสถานะเป็นสิ่งที่สะดุดตาที่สุด
- ใช้ได้ทั้งโหมดสว่างและมืดของแอป (canvas โปร่งใส ซ้อนบนพื้นหลังของหน้า)

## 4. อุปกรณ์

ตอนนี้ทำเป็นรูปทรงง่ายๆ จากโค้ดใน `src/components/building/equipment-models.tsx`:

| ประเภท (จากชื่อประเภทอุปกรณ์) | รูปทรง |
|---|---|
| Chiller | ตัวเครื่องกล่อง + คอมเพรสเซอร์ทรงกระบอก 2 ตัว + ท่อน้ำเย็น (ฟ้า) / น้ำร้อน (แดง) |
| Pump (ชื่อมี "pump" หรือ "ปั๊ม") | ฐาน + มอเตอร์ทรงกระบอกสีน้ำเงิน + ตัวปั๊มทรงกลม + ท่อ |
| เครื่องปรับอากาศ (ชื่อมี "ปรับอากาศ", "air", "ahu", "fcu") | ตู้ขาวมีช่องลม |
| อื่นๆ | กล่องเทา |

ที่ต้องการ: ยกระดับโมเดลเหล่านี้ให้ดูเป็นเครื่องจริงมากขึ้น (สัดส่วน วัสดุโลหะ/พลาสติก รายละเอียดสำคัญเช่น พัดลม คอยล์ ท่อ วาล์ว) โดย **ยังคงรูปทรงอ่านออกจากระยะไกลและโหลดเร็ว** ถ้าจะใช้ไฟล์ `.glb` ให้ใช้ไฟล์เล็ก (< 500 KB ต่อประเภท) และโหลดแบบ lazy ทุกเครื่องใช้โมเดลร่วมกันตามประเภท (instancing/clone) ไม่โหลดซ้ำ

เหนือแต่ละเครื่องมีลูกบอลสถานะ (`Beacon`): เขียว = ปกติ, เหลือง = เลยกำหนดบำรุงรักษา, แดง = ชำรุด/กำลังซ่อม สีเหลือง/แดงกะพริบเบาๆ ผ่าน `useFrame` (ไม่ใช้ CSS animation ดูข้อ 6) สีสถานะต้องไม่ใช้สีเพียงอย่างเดียวในการสื่อ (มีคำอธิบายสีด้านบนโมเดลและ aria-label ที่ปุ่ม)

## 5. ข้อมูลและพฤติกรรม

ข้อมูลมาจาก API จริง `GET /api/v1/assets?pageSize=100&sort=code` (hook `useApi` ใน `src/lib/use-api.ts`) แต่ละรายการ (`AssetListItem` ใน `shared/index.ts`):

```ts
{ id, code, name, type, brand, model, status, unit,
  location: string | null,   // "วิทยาเขต › อาคาร A1 › ชั้น 1 › ห้อง A101"
  lastMaintenance: string | null, nextDue: string | null }
```

- แยก **อาคาร / ชั้น / ห้อง** จากข้อความ `location` (ส่วนที่ขึ้นต้นด้วย "อาคาร", "ชั้น N", "ห้อง") อุปกรณ์ที่ไม่ระบุอาคารและชั้นจะไม่แสดง
- สถานะสี: `faulty` หรือ `under_repair` → แดง, `nextDue` ก่อนวันนี้ (เวลา Asia/Bangkok) → เหลือง, นอกนั้นเขียว
- UI ปัจจุบัน: เลือกอาคาร (dropdown ถ้ามีหลายอาคาร) → แท็บเลือกชั้น (มีจุดสีสถานะที่แย่ที่สุดของชั้น) → โมเดลของชั้นนั้น → กดเครื่อง → แผงข้อมูลเลื่อนจากขวา (`asset-drawer.tsx`) ปิดด้วย X, Esc หรือกดที่ว่าง
- การเลื่อนของแผงใช้ Web Animations API (`element.animate`) ห้ามเปลี่ยนเป็น CSS transition (ดูข้อ 6)
- ผังห้องจัดอัตโนมัติ (2 แถวหันหน้าทางเดิน) เพราะ **ยังไม่มีข้อมูลผังจริงในฐานข้อมูล** ถ้าจะให้ผังตรงของจริงต้องเพิ่มตาราง/คอลัมน์ตำแหน่งห้อง (ต้องผ่าน `db/schema.ts` + `npm run db:generate`) ถือเป็นงานแยก ถ้าจะทำให้คุยกับเจ้าของก่อน

## 6. ข้อจำกัดทางเทคนิค (สำคัญ)

- Next.js **16.4.5**, React **19.3**, `three` ^0.187, `@react-three/fiber` ^9.8, `@react-three/drei` ^10.7 ติดตั้งแล้ว
- **AGENTS.md ของ repo:** Next เวอร์ชันนี้ต่างจากที่รู้จัก ให้อ่าน `node_modules/next/dist/docs/` ก่อนเขียนโค้ดที่เกี่ยวกับ Next (เช่น `lazy-loading.md` สำหรับ `next/dynamic`)
- ตัวดู 3D ต้องโหลดแบบ lazy ฝั่ง client เท่านั้น: `dynamic(() => import("./building-3d"), { ssr: false })` เพื่อไม่ให้หน้าอื่นหนักขึ้น
- **ห้ามใช้ `<Html>` จาก drei:** มันสร้าง React root ซ้อนข้างใน แล้ว React 19 ล้มด้วย error "Attempted to synchronously unmount a root while React was already rendering" ปัจจุบันใช้ปุ่ม/ป้าย HTML วางทับ canvas แล้วคำนวณตำแหน่งจากจุด 3 มิติทุกเฟรมใน `Projector` (`useFrame` + `Vector3.project(camera)`) ให้คงแนวทางนี้ไว้ (ได้ ปุ่มที่ focus ได้ด้วยคีย์บอร์ด, `aria-label`, `title`)
- เครื่องของผู้ใช้ปิด "Animation effects" ของ Windows → `prefers-reduced-motion: reduce` และกฎที่ต้น `src/app/globals.css` ปิด CSS animation/transition ทั้งไซต์ ดังนั้นการเคลื่อนไหวต้องมาจาก `useFrame` หรือ Web Animations API จึงจะเห็น
- UI เป็นภาษาไทยทั้งหมด ฟอนต์ LINE Seed Sans TH มีธีมสว่าง/มืด ใช้ token สีของแอป (`bg-primary`, `text-muted-foreground`, `border-border` ฯลฯ) ใน HTML ส่วน 3D ใช้ค่าสีคงที่ได้
- ทุกปุ่มลบของแอปต้องมี popup ยืนยัน (ไม่เกี่ยวกับหน้านี้โดยตรง แต่ห้ามเพิ่มปุ่มลบโดยไม่มี popup)
- Dependency เพิ่มใหม่ต้องระวัง: host ต้องกด Run NPM Install เอง ถ้าไม่จำเป็นอย่าเพิ่ม

## 7. ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
|---|---|
| `src/app/building/page.tsx` | route `/building` (force-dynamic) |
| `src/components/building/building-view.tsx` | โหลดข้อมูล แยกอาคาร/ชั้น/ห้อง แท็บชั้น คำอธิบายสี ขนาดโมเดล |
| `src/components/building/building-3d.tsx` | ฉาก r3f: ผนัง พื้น แสง กล้อง `Plan`, `Beacon`, `Projector`, ปุ่ม/ป้ายซ้อนทับ |
| `src/components/building/equipment-models.tsx` | โมเดลอุปกรณ์แต่ละประเภท |
| `src/components/building/asset-drawer.tsx` | แผงข้อมูลเลื่อนจากขวา |
| `src/components/app-shell.tsx` | เมนู "อาคาร 3 มิติ" (ต่อจากทะเบียนอุปกรณ์) |

สัญญา (contract) ของ `Building3D`: `rooms: Room[]`, `extent: number`, `selected: number | null`, `onPick(id | null)` ที่ `Room = { name, items: { id, label, kind: "chiller"|"pump"|"air"|"other", alert: "ok"|"warn"|"bad" }[] }` พยายามคง props นี้ไว้ เพื่อไม่ต้องแก้ฝั่งข้อมูล

## 8. เกณฑ์ยอมรับ

1. เปิด `/building` แล้วเห็นแผนผังชั้นสไตล์ใกล้เคียงรูปอ้างอิง: ผนังมีมิติ แสงเงานุ่ม ไม่มีเฟอร์นิเจอร์ ไม่มีพื้น/กรอบสี่เหลี่ยมรอง ไม่มี card ครอบ
2. อุปกรณ์ Chiller/Pump/เครื่องปรับอากาศ แยกออกด้วยสายตาจากระยะไกล และสีสถานะเห็นชัด
3. ลากหมุนได้ ซูมได้ในช่วงจำกัด ไม่หมุนเอง
4. กดเครื่อง → แผงเลื่อนเข้าจากขวา; Esc/X/กดที่ว่างปิด; ใช้คีย์บอร์ดเลือกเครื่องได้
5. สลับชั้นแล้วกล้องไม่กระโดด
6. ไม่มี scrollbar ของหน้าที่ความสูงจอ ~768–1080px
7. `npm run typecheck` ผ่าน ไม่มี error ใน console โดยเฉพาะ error เรื่อง unmount root
8. โหลดหน้าอื่นไม่ได้ดึง three.js (ตรวจใน Network tab)
9. ทำงานทั้งโหมดสว่างและมืด
10. แสดงผลลื่นบนโน้ตบุ๊กทั่วไป (เงา 1 แสง, `dpr` ไม่เกิน 2)

## 9. สิ่งที่ผู้ใช้ไม่ชอบจากรอบก่อน (เรียนรู้จากข้อความของเขา)

- แผงข้อมูลตายตัวทางขวาของโมเดล (เอาออก ใช้แผงเลื่อนแทน)
- card ครอบโมเดล และพื้นสี่เหลี่ยมใต้โมเดล
- หมุนอัตโนมัติ
- คำอธิบายสีอยู่ใต้โมเดล (ย้ายขึ้นด้านบนแล้ว)
- โมเดลดู "ธรรมดา" ไม่มืออาชีพ ← จุดที่ต้องปรับปรุงมากที่สุดรอบนี้

## 10. ส่งมอบ

แก้ไฟล์ในข้อ 7 โดยตรง ไม่ต้องสร้างโครงสร้างใหม่ แล้วแจ้งว่าเปลี่ยนอะไร เพิ่ม dependency หรือไฟล์โมเดลหรือไม่ และ **อย่า push/commit เอง** ผู้ใช้เป็นคนสั่ง (เขาใช้ workflow: พัฒนาในเครื่อง ดูผลแล้วค่อยสั่ง push)
